# 区域选点、地点费用、营业参考、攻略与自动交通

## 本次行为

1. 区域游览：模型标记 `location_behavior=area`、`area_name`，服务端核实区域 POI，再从高德返回的真实子景点/公共入口中随机选一个通勤点。排除停车场、大巴设施、厕所、售票和管理设施。相同区域多次选点尽量不重复；刷新时保留已核实原点位。没有合适子地点时可用高德明确的入口坐标；明确区域没有可靠点位时保持未知，不生成随机经纬度。这个点仅表示区域通勤锚点，不代表已计算区域内部全部游览路线。
2. 地点费用：`Expense.stop_id` 关联具体活动，时间轴每个地点显示门票、餐饮等估算。新生成要求逐项计费；旧版日合计预算可以按地点分摊，显示“日预算分摊”，整数分合计保持不变，不伪装为该地点查询票价。高德人均消费仅作消费参考，不能转写成景点门票。缺价明确显示无参考，不视为免费。
3. 营业参考：服务端通过 `/v5/place/detail` 请求 `business,children,navi`，保存接口返回的周营业描述、查询当天时间、查询时间及公开地点链接。区域整体时间明确标为区域参考，不冒充选中子地点的时间。模型输入的营业声明会清除。查不到、权限不足、额度受限时保持未知；每次任务最多查询 40 个不同详情，失败缓存，避免可选信息无限请求。今日营业时间不直接套到未来出行日，预约与临时闭园仍需官方确认。
4. 攻略：旧版仅将粘贴正文放入提示并产生摘要，没有逐项落实检查，这是“摘要像参考了、行程差很多”的原因之一。本次新增默认 `guide_mode=prefer`，优先保留攻略地点与合理顺序；也可选 inspiration。模型需给出连续原文摘录、涉及地点、对应活动、采纳/调整/未采纳和原因。程序剔除虚构摘录、失效活动和不匹配的地点关联；只落实部分地点会降为“调整后采纳”，没有可核对记录会明确提示未落实。取舍原因仍是规划解释，不意味着攻略事实获官方确认。仅填链接不会自动抓取小红书或其他网页，需粘贴正文。
5. 自动交通：表单取消默认市内方式和比较开关；新规划使用 `mode=auto`，查询五种方式，按完整有效道路方案的 `duration_s` 选最小。接口返回多条路线时，也选有完整道路形状的最短耗时方案。并非声称已穷举所有现实路线。相同耗时依次偏好步行、公交、骑行、打车、自驾。打车/自驾复用道路请求；非首个驾车方案不套用首方案出租车估价，改用明确费率参考。候车、停车取车等未在接口内的耗时不编入分钟数，界面说明比较范围。
6. 用户仍能逐段手动切换交通，保存同一行程；`user_selected` 记录手动选择，刷新可用时保留。未手动选择的段落在刷新时重新比较。旧 API 仍可显式传五种市内方式；RouteLeg.mode 始终是实际方式，不会把 auto 当作地图接口模式。跨城交通独立处理。
7. 餐饮补充：优先考虑攻略推荐的餐馆/菜品和地域特色。推荐菜品与对应餐饮活动一起展示，高德返回的美食 tag 单独标注地图参考，不保证当天供应。附近餐厅替换时先尝试特色菜关键词，查不到再放宽；攻略优先模式保护明确提及的具体餐馆。尽量早餐07:00–09:30、午餐11:00–14:00、晚餐17:00–20:00；已核实的前后通勤和活动空档允许时，偏离时段的餐饮会有界调整，保持顺序和用餐时长，尊重用户显式时间。无空档则提示提前补餐；未安排正式餐饮时提醒沿途就餐或自带干粮、饮水，不虚构餐馆坐标。缺餐自理为待确认项，明确超常见时段才产生时间提醒。

## 接口增量

- TripRequest.mode 新默认 auto；guide_mode 为 prefer/inspiration，默认 prefer。
- Stop 新增 area_name、area_poi_id、anchor_note；location_behavior 增加 area。
- Stop.opening_hours_status 增加 map_reference；新增 opening_hours、opening_hours_today、opening_hours_scope=place/area、information_source、information_queried_at、average_cost_yuan。旧记录默认未知/空。
- Expense 新增 stop_id=''，仍是唯一预算记账来源，地点展示不另加费用。
- Itinerary.guide_decisions=[]：每条 `{source_index,excerpt,place_names,status,stop_ids,reason}`；status=adopted/adjusted/not_used。
- RouteLeg 新增 user_selected=false、selection_reason=''。route 端点设置手动标记；refresh 采用 auto 并保留有效手动选择；validate 仍不联网、不修改历史。
- Stop 新增 food_recommendations=[]、food_reference=''、meal_period=breakfast/lunch/dinner/空；DayPlan 新增 meal_note=''，显示缺餐、自理或偏时用餐提醒。
- 规则通过共享规范化 unknowns 输入传给 Python/仓颉，核心 JSON 校验协议未变。

- 完整回归：160 passed、1 skipped（本机仓颉原生不可用）；本次不以 Python 回退冒充原生通过。前端类型检查及 Vite 构建通过。
- 独立测试库真实生成颐和园—圆明园行程并核对最快交通、费用和营业参考。再次刷新保留已核实点位，不新增相同活动版本；明确区域休息也能落到同区域真实点位，不编造返程路线。
- 新增特色餐饮要求后再次真实生成：午餐 12:10，餐馆为御京轩烤鸭的具体分店，推荐烤鸭、京酱肉丝等；地图返回烤鸭、双人餐等商业特色字段。门票和餐饮预算关联具体活动，最终地图路线无阻断错误。菜品推荐不等于保证商家当天供应。
