# 2026-10-19 优化明细与交接

本次按“可信度 → 路线与安排 → 执行信息 → 攻略及本机服务保护”推进。目的地校验按用户要求跳过；同步远端后当前 checkout 仍为初始提交，未修改或自行重做该模块。没有提交、推送或改动原有行程数据库。

## 已实现

| 顺序 | 优化 | 实际行为与边界 |
|---|---|---|
| 1 | 地图故障分类 | 鉴权/签名、额度错误终止生成，不能保存为近似通过；同一请求内记住致命错误，避免重复访问。网络故障最多重试一次；取消和整次 180 秒上限保留。 |
| 1 | 路线缺失阻断 | `missing_location`、`missing_route` 从 unknowns 升级为 errors；旧版重新校验也使用新规则。缺少路线形状不能算已核实。 |
| 1 | 过去日期边界 | 新生成和修改请求在调用模型前拒绝过去日期（中国标准时间）；历史模型仍允许旧日期，读取和重新校验不受影响。 |
| 1 | 活动与检索地点分离 | Stop 新增 `place_name` 和 `location_behavior`；模糊餐饮区域保持未定位，多个相似分店不直接取第一个；返回城市再次核对。 |
| 1 | 原地休息 | 仅 break 可显式使用 `same_as_previous`，继承前一已核实地点；同地点转移标为 stationary、0 米/秒，不生成伪道路形状。未指定位置的自由活动仍阻断。 |
| 2 | 多方式比较 | 每段提供步行、自驾、公交地铁、骑行、打车候选，显示查询耗时、距离、费用可得性和注意事项。打车沿用驾车道路估算，不冒充网约车报价或候车时间。 |
| 2 | 用户逐段选择 | `POST /api/plans/{id}/route` 仅接受本版本已查询且可用的候选；不调用模型，保存新版本，重算当天交通费用和活动时间。 |
| 2 | 确定性时间修复 | 保留活动时长，仅向后顺延以容纳所选路线；无法在 23:59 前结束时不强行截断或跨午夜，保留原时间并报告。调整记录可见。 |
| 2 | 地点与路线刷新 | 独立 `/refresh` SSE，不调用模型，保留旧版和已选交通方式；`/validate` 继续只检查已有数据，不联网、不写历史。 |
| 2 | 局部修改及需求同步 | revise 可带完整 `trip` 和 `day_index`；仅修改当天时其他天的活动、时间和路线保留；日期/天数变更须整份修改，更换城市须重新生成。 |
| 3 | 费用覆盖 | 检查餐饮、过夜住宿、所选交通费用缺项；未取得交通票价仍列为未知，不将未知按免费计。公交票价按全员人数汇总。 |
| 3 | 酒店接驳与体力 | 提示词要求酒店作为到达/出发活动参与路线；缺少过夜末站酒店或次日首站酒店时提醒。增加每日步行量、景点数量与节奏检查。 |
| 4 | 攻略导入与摘要 | 最多 3 篇，每篇最多 6000 字，保留标题、可选来源链接、发布日期；Agent 生成带来源索引的经验摘要。拒绝 javascript 等非网页链接。 |
| 4 | 本机服务保护 | 限制 Host、浏览器跨来源请求，单进程最多 2 个规划任务，单次地图请求最多 3 个并发；健康检查增加成功/失败/取消次数及最近耗时，重启清零。 |
| 4 | 历史删除 | 可删除当前历史版本；不级联删除父子版本。其他历史记录不变。 |

## 接口与兼容

- 无新增第三方运行依赖，无新增 Key 或必需配置；货币仍以元输入、整数分汇总。
- 新字段均有默认值，保留原有 ID/父版本/版本号语义；旧记录无需迁移或删库。
- 交通枚举新增 `transit`、`bicycling`、`taxi`；`mode` 是默认方式，真实逐段选择以 `routes[].mode` 为准。
- `RouteLeg.alternatives` 保存已经查询的候选，包含道路形状；切换候选不会再次消耗外部服务额度。
- `RouteLeg.stationary` 只用于同一已核实地点；它是无需转移的记录，不是导航路线。
- 费用切换/刷新会移除对应天原先的模型交通总估算，重新加入已查询公交费用；自驾、打车、骑行费用仍需核实，因此总额可能是未完整覆盖的估算，校验会指出。
- Python/仓颉均将关键地点和路线缺失列为 errors。其余新增业务检查经 `pre_warnings` 统一传入两套引擎。

## 尚未完成的外部能力

1. **营业时间和预约的官方核验**：仍保留 unknown；攻略不能使该状态变成 verified。需要可靠的官方数据来源、时效和预约库存接口；当前不保证景点在指定时间开放或有预约名额。
2. **小红书自动搜索/抓取**：本次实现正文导入与摘要；只填链接不会自动读取。没有接入未核实授权和稳定性的抓取服务，也没有自动网页检索。
3. **公开多人部署**：当前仍是本机单用户原型。本机 Host/Origin 保护、并发上限不能替代账号鉴权、租户隔离、用户额度和持久任务队列；不应移除限制后直接公开部署。
4. **全面约束优化**：当前只做有界时间顺延和节奏提醒，未实现营业窗口求解、自动删景点、预约下单、无障碍核实或高铁/航班预订。
5. **原生仓颉运行问题**：需继续定位当前机器运行库/运行时兼容性；Python 的业务规则已同步，不以延长生产超时来掩盖问题。

- `tests/test_optimization.py`：新增回归。
