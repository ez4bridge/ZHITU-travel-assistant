# 当前实现介绍

源码核对：2026-10-20。下表介绍当前实现，后续小节按实际日期保留验证记录；早期“本地未提交”指当时状态。2026-10-14 的历史验收见 [验收记录](ACCEPTANCE.md)，不代表本轮原生仓颉已验收。

## 现在可以完整体验什么

用户先填写可选出发城市，再按顺序输入全国 1–5 个目的地及各城游玩天数、日期、人数、全员预算和跨城偏好 → 自动汇总总天数 → Agent 查询高德及可选铁路 → 输出结构化行程 → 服务端核对地点和路线、计算费用、执行规则 → 保存版本 → 页面展示每日活动、地图、预算和问题 → 用户提出一次修改 → 保存新版本并保留旧版。

| 功能 | 当前实现 |
|---|---|
| 需求表单 | 出发城市在上，目的地逐行添加；每城默认 1 天，合计向上取整为 1–10 天，1–50 人；可选出发交通与返回出发地，跨城偏好为铁路／飞机／长途汽车／自驾 |
| Agent | LangGraph 工具调用循环；工具结果返回模型，再输出 JSON |
| 地点核实 | 按每个活动所属城市限制搜索；缓存包含城市，跨城 POI ID 不能混用，保留未知状态 |
| 路线 | 高德真实步行/驾车距离、时长、道路形状，查询当日相邻活动之间的路线 |
| 费用 | 市内明细和独立跨城明细统一用 Decimal 取整到分、按全员汇总；跨城禁止在日费用里重复列出，价格均为估算 |
| 跨城交通 | 按城市顺序列出出发／到达日期时间和费用；可选铁路 MCP 查询直达时刻、席位快照和公布参考价，失败保留估算，其他方式仍估算；检查缺段、返程、时间重叠和到达顺序 |
| 校验 | 超预算、时间不合法/重叠、转移不足、重复景点、日期与缺项；营业时间和预约列为待确认 |
| 行程修改 | 每次点击执行一轮、沿用原需求，保存新版本和修改后的校验结果 |
| 地图与时间轴 | 日切换、当天城市地图筛选、地点联动、真实市内道路绘制；跨城单独展示，坐标 GCJ-02 |
| 历史 | SQLite 最近 50 条摘要、读取完整版本、父版本关联；数据保存在本机 |
| 取消 | 浏览器 AbortController，服务端取消进行中的任务并关闭客户端 |
| 仓颉 | 可选原生规则校验器，JSON stdin/stdout；本轮 Linux 使用 Python，原生编译／一致性仍待有 SDK 的环境执行 |

## 技术分别负责什么

- **Vue 3 / TypeScript / Vite**：页面、交互、类型检查、开发热更新和构建；自定义 CSS、Lucide 图标、原生 SVG 城市插画。
- **FastAPI / Pydantic 2**：HTTP、请求/输出数据结构、SSE 与同源静态页面。
- **LangGraph / OpenAI 兼容客户端**：管理消息与轮次，调用模型和本地 Python 工具。
- **HTTPX / 高德 REST 与 JS SDK**：城市地点、道路数据、底图；Web 安全密钥通过受限代理在服务端注入。
- **Decimal / Python / 可选仓颉**：费用和可重复的规则判定；大模型不负责最终算账和判定“通过”。
- **SQLite**：在本机保存完整 JSON 版本。

Agent 最多 8 轮，每轮至多执行 6 个工具调用；模型单请求超时 60 秒，高德 15 秒，整次生成/修改 180 秒，结构化 JSON 只修复一次。仓颉子进程上限 3 秒。这些限制均来自当前实现，改动时同步说明。
