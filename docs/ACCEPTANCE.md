# 首版验收记录

日期：2026-10-14（中国标准时间）。以下区分真实接口验证与自动化模拟，未测试范围不声称已通过。

## 环境与构建

- 独立 Python 3.11.7 环境；模型／LangGraph 关键版本沿用本机此前已验证的组合。
- 独立 Node 22.23.3，下载后对照官网 SHA256 校验；没有改动系统 Node 16。
- Vue 前端通过 TypeScript 检查和 Vite 生产构建；服务在 `127.0.0.1:7862` 同源提供页面与 API。
- `pip check` 无依赖冲突。
- 最终安装脚本用锁文件再次完成依赖安装与前端构建；前端运行依赖通过 npm 官方审计，未报告漏洞。
- 项目独立 Cangjie 1.0.5 Windows SDK，下载包 SHA256 与官网一致；校验源码实际编译通过。

## 真实接口验证

| 操作 | 结果 |
|---|---|
| 上海一日步行生成 | 约 30.39 秒；8 个已定位地点，8 段中 6 段可用真实路线；重复景点显示为问题 |
| 一日步行修改一次 | 约 26.41 秒；7 个已定位地点，6 段路线全部可用；新版本指向旧版本且旧版保留；剩余重复景点提示仍显示 |
| 上海三日驾车生成 | 约 41.44 秒；15 个已定位地点，12 段中 10 段可用；成功识别超预算、通行时间不足 |
| 浏览器地图 | 修正为一级 `/_AMapService` 代理后，底图、真实道路路线和地点标记正常显示；无浏览器错误日志 |
| 浏览器取消 | 点击生成后取消，表单恢复可操作，已有行程仍保留；后端取消运行任务 |
| 浏览器一日驾车生成和修改 | 原方案识别通行时间不足；用户修改一次后得到 3 个活动、2 段可用路线，预算估算 1140 元；仓颉检查通过，保留价格与营业时间的 4 项待确认信息 |
| 三日日期与地图联动 | 切换至第二天，时间轴与地图同时更新；点击地图标记 2，选中对应活动 `d2s2` |
| 窄窗口 | 390 px 视口下切换为单列，表单与结果区域约 343 px 宽，DOM 检查没有水平溢出；恢复桌面视口后布局正常 |

上述最初三次规划在 Python 校验后端完成。之后仓颉模块通过编译与一致性测试，并在服务健康检查与重新校验中启用。真实接口速度仅代表这些请求，不代表所有城市、日期或模型负载下的保证。

## 自动化与仓颉一致性

- 当前自动化功能测试 **24 项通过**：签名、整数分计算、人数与计费范围、分类费用与总额一致、时间冲突、通行时长向上取整、缺失数据、修改后重验、历史版本、秘密脱敏、无配置错误、城市限制、模型坐标丢弃、真实路线形状、两个并发请求隔离、断连取消、空白输入拒绝、一次 JSON 修复和修复失败终止等。
- 仓颉原生程序 **8 个固定样例 + 120 个随机样例** 与 Python 完全一致。随机样例组合费用、活动数量、时间冲突、重复地点、未知 POI、未知路线和转义文本。
- 中文、换行、引号、反斜杠、emoji 与 JSON Unicode 转义经过真实仓颉进程测试；非法 JSON 正常返回失败状态。
- 仓颉缺失、崩溃、超时、非法输出、一致性失败、运行期失败的 Python 回退路径通过模拟测试。没有故意触发系统级崩溃弹窗。

测试出现依赖库的弃用提醒，但没有测试失败。仓颉源码的控制台弃用用法已换为 `std.env`，最终构建没有该提醒。

## 验证条件

- 首版支持一个目的地城市、1–10 天、步行／驾车；真实接口重点验收上海 1 日／3 日，不代表其他城市与完整 10 日行程都经过验收。
- 价格是估算，营业时间与预约未核验；缺失 POI／路线标为未知，不能当成全部可行。
- 检测问题后依赖用户决定是否修改，一次修改不保证消除全部问题。
- 自动化格式／配置错误测试不调用付费接口；实际生成和修改会消耗模型与高德账号额度。

验收统计保存在本机 `.runtime`，界面截图位于 `docs/screenshots`；不会包含真实密钥。后续新增功能时应更新此记录，不把尚未验证的功能描述为完成。
